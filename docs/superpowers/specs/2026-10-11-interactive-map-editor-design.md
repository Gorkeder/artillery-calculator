# Интерактивная карта с редактором — дизайн

Дата: 2026-10-11. Статус: на ревью.

## Цель

На сайте ANOMA WIKI появляется страница `/map` с интерактивными картами игры.
Администратор рисует на них объекты прямо в браузере (точки, зоны, линии), создаёт
категории и прикрепляет к объектам текст и фото. Посетители видят результат сразу,
без правки кода и деплоя. Ориентир по функциям — stalzone.wiki/maps (слои, зоны
заражения, тайники), но данные редактируются через платформу, а не зашиты в код.

## Требования (согласовано)

- Правит администратор на сайте под паролем; данные хранятся на сервере и публикуются
  сразу. В будущем появятся обычные аккаунты, поэтому модель пользователей с ролями
  закладывается сразу.
- Несколько карт, у каждой своя картинка, категории и объекты.
- Типы объектов: **точка** (с иконкой), **полигон**, **линия**. Круги не нужны (их
  заменяет полигон). Подписей текстом на самой карте нет: подпись — это карточка
  объекта.
- Категории создаются в редакторе: название, цвет, иконка, тип фигуры, видимость по
  умолчанию. Для каждой категории есть фильтр на карте.
- У любого объекта есть собственный цвет (иначе берётся цвет категории), название,
  описание и несколько фото.
- Клик по объекту открывает квадратную карточку (на телефоне — выезжает снизу).
  Точка без иконки выглядит как «?».

- Редактор только для ПК, на телефоны не делать. Режим просмотра (карта, фильтры,
  карточки) адаптивный и работает на телефоне; на узком экране инструменты
  редактирования не показываются.

Вне охвата v1: отмена/повтор (Ctrl+Z), история изменений, импорт/экспорт, свои
иконки, видео, одновременная правка несколькими админами, массовое выделение,
тайловая нарезка карт, регистрация обычных пользователей.

## Архитектура

- **Фронтенд:** `map.html` (без сборки, как остальные страницы). Leaflet с
  `CRS.Simple` показывает картинку карты; Leaflet-Geoman даёт рисование и правку
  вершин. Файлы библиотек лежат в репозитории (без CDN: внешние ресурсы в РФ
  нестабильны). Оформление в палитре сайта (`#121212`, `#d4c24f`).
- **Бэкенд:** `server/` — Node 22 без npm-зависимостей (`node:http`, `node:sqlite`,
  `crypto.scrypt`). Слушает `127.0.0.1:3000`, nginx проксирует `/api/`.
- **Хранилище:** SQLite `/var/lib/anoma/db/anoma.db` (каталог `db/` с правами 0700
  и владельцем `anoma`: в базе хэши паролей), загрузки `/var/lib/anoma/uploads/`
  (читаются nginx). Оба пути вне `/var/www/anoma`, rsync их не затрагивает.

## Модель данных

| Таблица | Поля |
|---|---|
| `users` | `id`, `login`, `password_hash`, `role` (`admin`/`user`), `created_at` |
| `sessions` | `token_hash`, `user_id`, `expires_at` |
| `maps` | `id`, `slug`, `title`, `image_path`, `width`, `height`, `sort`, `published` |
| `categories` | `id`, `map_id`, `name`, `color`, `icon`, `shape` (`point`/`polygon`/`line`), `visible_default`, `sort` |
| `features` | `id`, `map_id`, `category_id`, `geometry` (JSON), `title`, `description`, `color` (nullable), `opacity` (nullable), `author_id`, `status` (`approved`/`pending`, по умолчанию `approved`), `updated_at`, `updated_by` |
| `feature_images` | `id`, `feature_id`, `path`, `sort` |

Геометрия в `features.geometry`: точка `{x, y}`; полигон и линия `{points: [[x, y], …]}`.
Координаты — **доли ширины/высоты картинки (0..1)**, поэтому замена картинки на
версию с другим разрешением не ломает разметку.

## API (JSON, префикс `/api`)

Публичное чтение:
- `GET /maps` — список опубликованных карт.
- `GET /maps/:slug` — карта с категориями и всеми объектами (с фото) одним ответом.

Только `admin`:
- `POST /login`, `POST /logout`, `GET /me`.
- CRUD `/maps`, `/categories`, `/features`.
- `PUT /maps/:id/image` и `PUT /features/:id/images` — тело запроса: сырой файл с
  `Content-Type: image/png|jpeg|webp`, без multipart.

Правки сохраняются сразу при завершении действия; в интерфейсе виден статус
«Сохранено» / «Ошибка, повторить». Конфликты правок: побеждает последняя запись.

## Интерфейс

Режим просмотра (всем):
- Карта на весь экран: зум колесом/жестами, перетаскивание.
- Левая панель: переключатель карт, список категорий с чекбоксами (цвет, иконка,
  «показать все/скрыть все»); на телефоне сворачивается в ящик.
- Клик по объекту — карточка: название, описание (простой текст), галерея фото
  (клик — крупнее). Закрытие: крестик, клик мимо, Esc.
- Поиск по названиям объектов (подсветка + центрирование).
- Постоянная ссылка на объект: `/map?m=<slug>&f=<id>`.

Режим редактора (после входа через иконку замка):
- Панель инструментов: выбор/перемещение, точка, полигон, линия, удалить. Категория
  выбирается слева.
- Полигон/линия: клик по вершинам, завершение двойным кликом или Enter, Esc —
  отмена; вершины перетаскиваются, на ребре можно добавить узел.
- Правая панель свойств: название, описание, категория, цвет и прозрачность, фото.
- Менеджер категорий (встроенный набор SVG-иконок, ~20–30 штук) и менеджер карт
  (добавить, загрузить/заменить картинку, порядок, опубликована ли).
- Фото сжимаются в браузере до 1600 px по длинной стороне перед загрузкой.

## Расширяемость под обычные аккаунты

В v1 пишет только `admin`, но карта не должна переписываться, когда появятся
обычные пользователи. Для этого в v1 закладывается:

- **Единая проверка прав** `can(user, action, resource)` в одном модуле сервера. Все
  эндпоинты записи вызывают только её. В v1 она возвращает «только admin»; позже
  добавляется правило вроде «пользователь создаёт и правит свои `pending`-объекты».
  Проверок `role === 'admin'` вне этого модуля быть не должно.
- **`author_id` и `status`** у объектов (см. модель данных): предложения от
  пользователей и модерация становятся фильтром по статусу, а не миграцией.
- **Выдача по статусу:** публичное чтение возвращает только `approved`; автору — ещё
  и его `pending`; админу — всё.
- **Редактор — тот же компонент**, режим которого определяется правами из `GET /me`
  (что можно создавать, править, удалять), а не жёстким «админ/не админ» во
  фронтенде.
- Регистрация, подтверждение почты, сброс пароля, лимиты на пользователя — отдельные
  будущие задачи поверх этого; карту и модель данных они не меняют.

## Безопасность

- Админ создаётся командой на сервере (`node server/cli.js create-admin`); пароль
  не хранится ни в репозитории, ни в вебе. Хэш — scrypt.
- Сессия: cookie `HttpOnly; Secure; SameSite=Strict`, 30 дней, токен хранится в БД
  хэшем. Запросы записи требуют заголовок `X-Requested-With`.
- Лимит попыток входа: в приложении и в nginx (`limit_req`).
- Пользовательский текст выводится только через `textContent`; HTML не
  поддерживается.
- Загрузки: тип по сигнатуре файла (PNG/JPEG/WebP, SVG запрещён), лимит 8 МБ,
  случайные имена; nginx отдаёт `/uploads/` с `X-Content-Type-Options: nosniff`.
- Запись доступна только роли `admin`.

## Деплой

- nginx: `location /api/` (proxy на `127.0.0.1:3000`, `client_max_body_size 8m`),
  `location /uploads/` (alias на `/var/lib/anoma/uploads/`), `location = /map`
  (на `map.html`).
- systemd-сервис `anoma-api.service`, код в `/opt/anoma-api`. Перед началом
  реализации проверить версию Node на VPS: `node:sqlite` требует 22.5+ (без флага —
  22.13+); при несовпадении обновить Node, а не добавлять нативную зависимость.
- `.github/workflows/deploy.yml`: добавить синк `server/` и перезапуск сервиса;
  `server/` не попадает в синк статики, `map.html` и файлы Leaflet попадают.
- Перед релизом проверить, что ежедневный бэкап SQLite на VPS покрывает новый путь
  БД.
- Стартовая карта: одноразовый скрипт превращает текущий `map.js` в PNG и создаёт
  запись в `maps`. Калькулятор `art-calc.html` и `map.js` не меняются.
- Обновить `CLAUDE.md`: появился `server/` с отдельным деплоем (раздел «no build
  step» остаётся верным для статической части).

## Тестирование

- Серверная логика (авторизация, права, валидация геометрии и загрузок, CRUD) —
  тесты на `node --test`, как в `tools/*.test.js`.
- Фронтенд: ручная проверка по чек-листу в браузере (рисование, правка вершин,
  фильтры, карточка, мобильный вид), без тестового фреймворка.
