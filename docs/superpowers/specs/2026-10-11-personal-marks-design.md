# Личные метки пользователей (этап C) — дизайн

Дата: 2026-10-11. Статус: реализовано в ветке `personal-marks`.

Продолжает спеки [карты](2026-10-11-interactive-map-editor-design.md) и
[аккаунтов](2026-10-11-user-accounts-design.md) (этап A).

## Цель

Вошедший пользователь ставит на карте **личные метки** (точки, полигоны, линии) с названием,
описанием, цветом и иконкой. Метки видит только их автор, на любом устройстве после входа.
Общая карта и модерация (этап B) не затрагиваются.

## Решения (согласовано)

| Вопрос | Решение |
|--------|---------|
| Кто видит метку | Только автор. Никакого шаринга, ссылок для других, групп |
| Оформление | Без категорий: форма (точка/полигон/линия), цвет, иконка из встроенного набора. Один общий фильтр «Мои метки» |
| Фото | Нет. Только название и текстовое описание |
| Устройства | Создание и правка только на ПК (как у админа). На телефоне метки видны и открываются карточкой |
| Хранение | Отдельная таблица `user_marks`, а не строки `features` со статусом |
| Подтверждение почты | Не создаёт сессию (см. «Предварительное исправление») |

### Почему не `features` со статусом

`features.category_id NOT NULL`, а публичные запросы читают `features` напрямую. Любой запрос
без фильтра по статусу стал бы утечкой чужих тайников. Статус `pending` к тому же зарезервирован под
этап B (модерация), и смешивать два смысла нельзя. Отдельная таблица физически отделяет личные
данные от публичной выдачи.

## Предварительное исправление: подтверждение почты не входит само

Сегодня `POST /api/verify-email` создаёт сессию (`server/routes/account.js`). Злоумышленник
может зарегистрироваться на чужую почту со своим паролем: жертва перейдёт по ссылке, окажется в
его аккаунте и начнёт сохранять туда личные метки. Для публичной карты это не страшно,
для приватных меток — утечка.

- `/api/verify-email` помечает почту подтверждённой и **не** вызывает `createSession`,
  не ставит cookie. Ответ: `{ ok: true }` (раньше — `meBody`).
- `account.js` (`showVerify`): после успеха показывает «Почта подтверждена. Войдите» и форму входа
  (как после сброса пароля), без `afterLogin`.
- Тесты `account.test.js`, которые ожидали сессию после подтверждения, обновляются.
- Это отдельный коммит, идущий первым: он нужен независимо от остальной фичи.

## Модель данных

Миграция 3 (`MIGRATIONS` в `server/db.js`):

```sql
CREATE TABLE user_marks (
  id INTEGER PRIMARY KEY,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  map_id INTEGER NOT NULL REFERENCES maps(id) ON DELETE CASCADE,
  shape TEXT NOT NULL CHECK (shape IN ('point', 'polygon', 'line')),
  geometry TEXT NOT NULL,
  title TEXT NOT NULL DEFAULT '',
  description TEXT NOT NULL DEFAULT '',
  color TEXT NOT NULL DEFAULT '#d4c24f',
  icon TEXT NOT NULL DEFAULT 'question',
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX idx_user_marks_user_map ON user_marks(user_id, map_id);
```

- `geometry` в том же формате, что у `features`: точка `{x, y}`, полигон/линия `{points: [[x, y], …]}`,
  доли 0..1. Проверяется существующим `validateGeometry` из `server/validate.js`.
- Форма (`shape`) задаётся при создании и дальше не меняется.
- `icon` проверяется тем же `ICON_RE`, что у категорий; для полигонов и линий игнорируется при показе.
- Каскады: удаление пользователя или карты удаляет метки.

## Лимиты

| Что | Значение | Где проверяется |
|-----|----------|-----------------|
| Меток на пользователя (всего) | 300 | сервер, при создании → 409 `marks_limit` |
| Вершин у полигона/линии | 100 (поверх `MAX_POINTS = 2000` у `validateGeometry`) | сервер → 400 |
| Название | до 80 символов | сервер |
| Описание | до 1000 символов | сервер |
| Частота записи | 120 запросов записи за 10 минут на пользователя | лимитер приложения `marksWrite` в `app.js` рядом с существующими |

## API

Все маршруты требуют сессию (иначе 401). Все ответы API уже идут с `Cache-Control: no-store` (`sendJson`), отдельной настройки не требуется.
Запись требует `X-Requested-With`, как все не-GET запросы.

| Запрос | Тело | Поведение |
|--------|------|-----------|
| `GET /api/my/marks?map=<slug>` | — | Метки текущего пользователя на опубликованной карте. Нет карты → 404 |
| `POST /api/my/marks` | `{map, shape, geometry, title?, description?, color?, icon?}` | Создаёт, 201 + метка. Лимиты выше |
| `PATCH /api/my/marks/:id` | любые из `geometry, title, description, color, icon` | Обновляет, меняет `updated_at`. Форма не меняется |
| `DELETE /api/my/marks/:id` | — | Удаляет, 200 `{ok: true}` (как остальные DELETE) |

Метка в ответе: `{id, map, shape, geometry, title, description, color, icon, created_at, updated_at}`.

Публичные `GET /api/maps` и `GET /api/maps/:slug` **не меняются** и метки не содержат.

### Права

`server/permissions.js` получает действия `mark:create`, `mark:update`, `mark:delete`:

- `mark:create` — любой вошедший пользователь (включая админа);
- `mark:update` / `mark:delete` — только если `resource.user_id === user.id`.

Чужая или несуществующая метка в `PATCH`/`DELETE` отвечает одинаково: **404**, а не 403, чтобы
нельзя было перебирать id. Проверок `role` вне `permissions.js` не добавляется.

`GET /api/me` (`server/me.js`): в объект `can` добавляется `marks: true` для вошедшего, `false` для гостя
(ключ добавляется в `capabilities()` из `permissions.js`).

## Интерфейс

- **Просмотр** (`map-app.js`): слой «Мои метки» с общим чекбоксом-фильтром в левой панели. Гостю
  вместо фильтра показывается подсказка «Войдите, чтобы ставить свои метки» со ссылкой на `/account`.
  Клик по метке открывает ту же карточку, что у объекта (название, описание; без галереи).
  Метки загружаются отдельным запросом после `GET /me`, чтобы публичная карта не ждала приватных данных.
- **Редактор** (`map-editor.js`, `map-editor-dialogs.js`): сейчас подгружается после входа админа на ПК.
  Теперь условие — `me.can.marks` на ПК. У обычного пользователя редактор работает только в режиме
  «Мои метки»: инструменты точка/полигон/линия/выбор/удалить, панель свойств с названием, описанием,
  цветом и иконкой, без категорий, прозрачности и фото. У админа вверху переключатель
  «Общие / Мои». Режим определяется возможностями из `GET /me`, не проверкой роли.
- **Ссылка на метку:** `/map?m=<slug>&mark=<id>`. Работает только у владельца, у остальных
  параметр молча игнорируется.
- **Телефон:** метки видны и открываются карточкой, инструментов правки нет (как у админа сегодня).
- Сохранение — как в редакторе карты: сразу при завершении действия, статус «Сохранено» / «Ошибка, повторить».
- Пользовательский текст выводится только через `textContent`.

## Приватность

- Данные меток видны только владельцу: ни один API-маршрут и ни один экран, включая админский,
  не отдаёт чужие метки. Технически они лежат в той же БД, к которой имеет доступ владелец сервера,
  и это нужно честно отразить в `/privacy`.
- Метки удаляются вместе с аккаунтом (каскад). Самоудаление аккаунта вне этапа C, пока — по
  просьбе, адресованной администратору.
- `privacy.html`: добавляется абзац — какие данные хранятся (координаты, название, описание, цвет),
  кому видны (только вам; администратор сервера технически имеет доступ к базе), как удалить.
- Бэкап БД уже покрывает новую таблицу (тот же файл).

## Тестирование

Серверные тесты на `node --test` (новый файл `server/test/marks.test.js`):

- создание, чтение, правка, удаление своей метки; валидация формы, геометрии, цвета, длин;
- **изоляция**: пользователь B не читает метки A (`GET` возвращает только свои), `PATCH` и `DELETE`
  чужой метки → 404, метка A не меняется;
- гость → 401 на всех четырёх маршрутах;
- публичные `GET /api/maps` и `GET /api/maps/:slug` не содержат меток;
- лимиты: 300 меток → 409, 101 вершина → 400, частота записи;
- каскад: удаление пользователя и карты удаляет метки;
- миграция 3 на базе версии 2 сохраняет существующие данные;
- `/me` отдаёт `can.marks`; `permissions.test.js` расширяется новыми действиями;
- `/api/verify-email` подтверждает почту, не отдаёт `Set-Cookie`.

Фронтенд — ручной чек-лист (как для карты): гость, обычный пользователь на ПК (рисование, правка вершин,
удаление, фильтр, перезагрузка, второй браузер под тем же аккаунтом), обычный пользователь на 375 px
(метки видны, правки нет), админ (переключатель «Общие / Мои», общая карта работает как раньше),
два разных пользователя не видят меток друг друга.

## Раскатка

1. Бэкап БД, затем деплой (миграция 3 выполняется при старте `anoma-api`, как миграция 2).
2. Ветка вливается в `master`; пуш деплоит и статику, и `server/`. Порядок коммитов в ветке: сначала
   исправление подтверждения почты, затем остальное.
3. Проверка на проде: регистрация нового тестового пользователя, подтверждение (сессии нет, вход вручную),
   метка, перезагрузка, проверка из второго аккаунта.
4. В `CLAUDE.md` обновляется раздел «Статус проекта»; `RELEASE.md` — строка про миграцию 3.

## Вне объёма

Шаринг и группы; фото; пользовательские категории; импорт/экспорт; правка с телефона; отмена/повтор;
самоудаление аккаунта; предложения общих точек с модерацией (этап B).
